공개 링크: https://lkw5406-png.github.io/insta-research/ (첫 화면은 3개를 합친 [전체] 목록. 바로 열기: `#all`, `#instagram`, `#pinterest`, `#runway`)
(파일 이름은 처음 만든 그대로 둠 — 매뉴얼 새로 만들기·삭제는 사장님 허락 필요)

## 목표
사장님이 인스타그램·핀터레스트·런웨이에서 캡처한 사진 중 **패션 사진만** 골라, **사진 부분만** 잘라서, **사진마다 출처**를 적고
여성/남성·아이템·스타일·컬러·소재로 분류해 사이트의 목록 3개에 정리한다. 실행은 **사장님이 말씀하실 때**
("리서치 보드 정리해줘", "인스타 정리해줘" 등 — 폴더 3개를 한 번에 처리).

| 목록 | 넣는 폴더 | 출처(source) 적는 법 |
|---|---|---|
| 인스타그램 | `inbox/인스타그램` | 게시물 맨 위 계정 `@아이디` (프로필 링크 자동) |
| 핀터레스트 | `inbox/핀터레스트` | 핀 올린 계정 `@아이디` (핀터레스트 프로필 링크 자동). 원래 사이트가 보이면 `origin` |
| 런웨이 | `inbox/런웨이` | `브랜드 시즌` (예: `Prada 2027SS`). 캡처한 사이트가 보이면 `origin` (예: `vogue.com`) |

**사진 번호**: 목록별 `IG-0001`(인스타그램) / `PT-0001`(핀터레스트) / `RW-0001`(런웨이). 합칠 때 자동으로 붙음 —
inbox 파일은 `IG-0023_출처.png`로 이름이 바뀌고, 사이트 사진 왼쪽 위와 크게 보기에 같은 번호가 보임. 사이트 검색칸에 번호·계정을 넣으면 바로 찾음.
손으로 판정표를 고친 뒤 번호가 빠졌으면 `--codes`로 다시 맞춤(이미 붙은 번호는 안 바뀜).

폴더 이름은 `tools/common.py`의 `BOARDS`. inbox 바로 아래나 모르는 폴더에 넣은 파일은 인스타그램으로 들어감.

## 원칙 (2026-09-26 사장님과 정함)
- **캡처는 사장님이.** 인스타·핀터레스트는 자동 수집을 금지하고(robots.txt), 공식 API는 저장 게시물을 못 읽음.
  Claude가 사장님 계정에 로그인해 캡처하는 건 하지 않음 — 걸리면 계정이 정지될 수 있음. 사장님이 다시 요청해도 이유를 짧게 설명.
- **비용 0원.** 판정은 Claude가 대화 안에서 사진을 직접 봄(유료 API 없음).
- **공개 링크(깃허브)는 사장님 결정.** 다른 사람 사진이라 저작권 위험을 줄이는 장치를 꼭 지킴:
  검색 차단(noindex + docs/robots.txt), 공개는 **긴 변 480px 축소본만**, 모든 사진에 출처 계정 + 인스타 프로필 링크.
  원본 캡처(inbox/)·잘라 낸 원본(photos/)은 절대 저장소에 올리지 않음(.gitignore).

## 사장님이 하실 일 (캡처 요령)
1. 인스타 → 프로필 → ☰ → 저장됨 → 게시물을 하나씩 열어 **스크린샷**.
   - 게시물 **맨 위 계정 이름이 보이게**(출처 기록용), **사진 전체가 보이게**. PC 인스타 화면을 캡처(Win+PrtSc)해도 됨 — 사진+계정줄이 한 화면에 나와서 편함.
   - 여러 장짜리(캐러셀)는 넘기면서 장마다 캡처.
   - 핀터레스트: 핀을 열어 사진과 **핀 올린 계정 이름**이 보이게. 런웨이: 사진과 **브랜드·시즌 글자**(쇼 제목)가 보이게.
2. 캡처를 목록에 맞는 폴더에 저장: `바탕화면/인스타 리서치/inbox/인스타그램`, `…/핀터레스트`, `…/런웨이`.
   (폰 캡처는 카카오톡 나와의 채팅 → PC 카톡 '모두 저장'. 같은 사진을 두 번 넣어도 한 번만 처리)
3. "리서치 보드 정리해줘"라고 말씀.

## Claude 순서
Pillow가 필요하므로 모든 명령은 `uv run -q --with pillow python ...` (작업 폴더: `바탕화면/인스타 리서치`).
1. `tools/inbox_queue.py --next --size 30` → 새 스크린샷 목록 + `.tmp/sheet_N.jpg`(3장씩, 왼쪽 빨간 눈금 0=맨 위 ~ 10=맨 아래).
   같은 게시물을 두 번 캡처한 건 자동으로 '중복' 처리됨.
2. 판독용 이미지를 **하나씩 Read로 보고** 판정 파일 `.tmp/batchN.json` 작성 (형식은 `inbox_queue.py` 맨 위 설명).
   - `crop`: 사진 부분만 [왼쪽, 위, 오른쪽, 아래] 비율. 눈금 숫자 ÷ 10 (예: 1.7~7.4 → 0.17, 0.74). 계정줄·좋아요줄·글은 빼고,
     사진 가장자리를 1~2% 안쪽으로. 한 캡처에 사진이 여러 장 보이면 `[[...], [...]]`.
   - 판독용 이미지 제목에 `[인스타그램]` 같은 목록 이름이 적혀 있음 → 목록에 맞는 출처 규칙(맨 위 표).
   - `source`: 인스타·핀터레스트는 계정 이름 그대로 `@아이디`, 런웨이는 `브랜드 시즌`. 안 보이면 `"확인 불가"` + `source_note`에 이유(예: "캡처에 계정줄 잘림").
     추측으로 채우지 않음. 사진 안 태그(@)는 출처가 아님 — 원하면 summary에 "착용: @..."로.
   - 키워드는 `tools/trend_keywords.json` 이름표만(매거진 리포트와 같은 말). 확실한 것만.
3. `--merge .tmp/batchN.json` → 문제가 있으면 아무것도 안 합치고 목록을 보여 줌 → 고쳐서 다시.
4. 남은 게 있으면 1~3 반복. 끝나면 `--check --review 12` → `.tmp/review.jpg`를 보고 잘못 잘린 사진이 있으면
   판정표(`data/photo_labels.json`)의 crop을 고친 뒤 해당 사진 파일(photos/, docs/img/)을 지우고 그 id만 다시 판정.
5. `tools/build_report.py --publish` → `docs/`(공개용). PC 전용 원본 크기 보기는 옵션 없이 → `report/index.html`.
6. `git status`로 inbox/·photos/·.env가 안 올라가는지 확인 → `git add data docs tools workflows` → 커밋 → `git pull -q --rebase` → 푸시.
7. 사장님께 보고: 새 사진 몇 장(패션/아님/중복), 출처 확인 불가 몇 장(있으면 다음 캡처 때 계정줄이 보이게 부탁), 링크.

## 판정 기준
- **패션 O**: 옷·신발·가방·액세서리 착장이 주인공인 사진 — 스트리트 스냅, 룩북, 화보, 셀럽 착장, 제품 컷, 런웨이.
- **패션 X**: 음식, 풍경·인테리어, 밈·글 이미지, 메이크업·헤어만, 반려동물, 광고 문구만 있는 이미지.
- 애매하면(옷이 조금 보이는 여행 사진 등) 디자이너 참고가 될 만큼 옷이 잘 보이면 O.
- gender: 입은 사람 기준 여성/남성, 제품 컷·둘 다면 공용.

## 문제가 생겼을 때
- HEIC(아이폰 원본 사진) 파일: 스크린샷은 PNG라 보통 문제 없음. HEIC가 오면 사장님께 스크린샷으로 다시 부탁하거나
  `--with pillow-heif`로 여는 기능을 추가(추가하면 이 매뉴얼에 기록).
- 계정 이름 글씨가 작아 안 읽힘: 원본 파일(`inbox/...`)을 직접 Read로 열어 확인.
- 화면 점검용 Edge 헤드리스 캡처는 창 폭을 400으로 줘도 실제로는 약 492px로 그려서 오른쪽이 잘려 보임 — 페이지 문제가 아님.
